# portable-devshell v1.0.0-rc.1

首个 **1.0.0 Release Candidate**，在 v1.0.0-beta.2 发布之后的 beta.3 开发周期和多轮收口审查基础上形成。RC 仍为预发布版本，不代表稳定版或承诺与早期 Beta 的无条件兼容。

## 本次变化

- **ToolCall / Transport**：收敛调用入口，强化 RPC/Stream 与 Channel、Context、Instance 的生命周期归属；断开或重连时保留正确的原始请求关联，防止重复交付有副作用的操作。
- **Worker / tmux**：增强 PTY/进程组生命周期与清理、输出字节背压、终端记录的持久化和恢复；改进 Reverse Worker 重注册时的显式替换和旧连接保护。
- **CLI / TUI / Web / MCP App**：修正初始化、SSH 与终端输入恢复、审批与 Workspace 状态反馈、编辑草稿保护、Audit/活动查询；默认减少普通 ToolCall 的 Inline UI 开销，Fullscreen 保持可用。
- **Agent / Extension / MCP**：保留批量编辑错误证据，正确传递 Comment 到外层调用方结果，修复文件读取长行、Watch 批量事件和订阅公平性。
- **安装和构建**：从 DevShell 自身 Worker 工具调用发起自升级时明确拒绝，保持独立终端升级路径；修正 MCP App 构建依赖关系，并完成 Windows PowerShell 安装器对应约束。

## 发布前验证

功能代码基线 `6d46905b` 上的主 CI 和正式 `dev1.0.0-beta.3-1` push CI 各 **8/8** 通过，覆盖 Linux、macOS、Windows 的 x64/arm64 与 macOS 专项合约。扩展 CI 四组（完整功能链、Extension、真实升级迁移回滚、Windows psmux）也均通过。RC 版本提交仍须按仓库发布工作流在**同一提交**完成开发标签 CI 后才能创建此 Release。

## 升级与兼容边界

版本号并不能替代 Control/Worker/Frame、Extension API 与持久化 schema 各自的兼容性协商。升级可能需要客户端、Worker、OAuth 会话重连；不得仅因为传输确认丢失而重复执行有副作用的 ToolCall。

本地运行环境由维护者定义为可信；本地 Audit 和 Secret 的存储形式本身不是 RC 阻断项。外部 OAuth、MCP 授权与真实部署环境仍按各自的信任边界进行控制。
