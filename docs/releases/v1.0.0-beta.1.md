# portable-devshell v1.0.0-beta.1

This is the first **1.0 Beta** release. It builds on alpha.4 with stronger
recovery after interrupted operations, more consistent results across clients,
and broader end-to-end testing. It is still a prerelease, not a stable API or
an exactly-once execution guarantee.

## What's changed since alpha.4

1. **Reliable state changes and recovery.** Config updates now distinguish a
   completed commit from a write whose durability is uncertain. Restart and
   cleanup paths preserve the last recoverable state instead of accidentally
   rolling back a committed generation or dropping unrelated Instances. Todo
   revisions, historical Message databases, and Extension cleanup also recover
   more consistently after partial failures.
2. **ToolCall, Approval, and Audit.** Duplicate call IDs cannot overwrite the
   original execution's Audit identity. When a ToolCall has already executed
   but its response processing fails, callers receive completion metadata and
   are not told that blindly retrying is safe. Concurrent Approval decisions
   and stale UI updates are isolated. WebUI can act on pending approvals before
   the first ToolCall Audit entry exists, and retains Audit history on reload.
3. **Reverse and Instance lifecycle.** Reverse WSS/SSE candidate connections
   no longer consume the previous live connection's reliable-frame state.
   Stopped self-managed Reverse Workers can be deleted and re-enrolled without
   Control trying to manage their remote process. Container adoption retains
   verified resource ownership through supported lifecycle changes; unknown
   ownership is not guessed from a reused container name.
4. **OAuth and Extension handling.** Concurrent refresh requests use a single
   durable token rotation; replay revokes the affected token family. OIDC
   state migration and signing-key initialization are more robust. Extension
   reload, retirement, and in-flight streams retain their correct generation
   and can retry incomplete cleanup.
5. **Model commands and UI.** Bundled model-facing commands, including
   `devshell recall`, are exposed through their intended Context-scoped
   permissions. The bundled `direnv` Extension is included in installation.
   MCP App, TUI, and WebUI better handle delayed responses, Context changes,
   and conflicting operations.

## Upgrading

- Upgrade an existing alpha installation using the normal DevShell installer
  or update workflow. Keep a backup of persistent configuration and databases
  before upgrading; supported migration depends on the stored schema, not
  only the previously installed executable version.
- Existing connections may need to reconnect and refresh their MCP tool
  catalog after an upgrade. Review separately installed Extensions for API
  compatibility before re-enabling them.
- This release does not automatically assume ownership of a running external
  container when its previous identity cannot be verified.

## Verification and current limits

- The Linux x64 common CI, native Worker and app packaging, installer smoke,
  real local/Reverse Worker calls, Chromium Audit persistence, and Instance
  Stop/Start passed release-candidate testing. A 180-second tmux handoff also
  completed and its result was recovered.
- Four isolated complete functional chains passed: Artifact transfer and
  recovery; Wait/Reentry across restarts; CLI/Web/MCP consistency; and Reverse
  enrollment, reconnection, deletion, and re-creation. The v0.7.7 upgrade
  matrix covers real persistent-state migration and rollback scenarios.
- Real ChatGPT Host delivery, physical cross-machine network failures, actual
  Docker/Podman engines, and Windows runtime interaction still need broader
  field testing. Six-platform CI and release-asset verification are required
  separately for the final tagged commit.
- If a connection drops after a side-effecting command has started, do not
  assume it is safe to run that command again. Check execution and Audit state
  before retrying.
