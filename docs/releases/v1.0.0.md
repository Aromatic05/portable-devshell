# portable-devshell v1.0.0

**首个正式稳定版 · 2026 年 11 月 5 日**

经过 Alpha、Beta 和 Release Candidate 阶段的持续开发、重构与验收，**portable-devshell 1.0.0 正式发布**。

与 v0.7.7 相比，1.0.0 不只是版本号升级：Instance、Transport、ToolCall、Context 与 Extension 已收敛为统一的运行模型，并重点完善跨设备执行、持久化任务、多端交互、生命周期恢复和正式版安装升级。

## 主要更新

### 统一的 Instance 与 Control 架构

- 支持 **Local、SSH、Docker、Podman、Reverse** 五种运行环境。
- 由 TypeScript Control daemon 统一管理 Instance 注册、配置、生命周期、连接和状态；每个目标环境通过独立的 Rust Worker daemon 执行操作。
- CLI、TUI、WebUI 和 MCP 共享 Control 的权威状态，不再各自维护独立的 Instance 管理链路。
- Context 按 Instance 绑定 Workspace；跨 Instance 访问通过显式授权的远程附加流程进行。

### Transport 与 ToolCall 统一

- 收敛 Frame、Envelope、Endpoint、Channel、Session 与路由模型，明确通信协议和生命周期边界。
- 将工具调用统一至 ToolCall，贯通 **Review、Rewrite、目标选择、执行、Audit** 等处理阶段。
- 强化请求归属、连接代际切换、取消传播、流控和断线后的状态恢复，隔离过期连接与旧运行代际。
- 对已执行但响应丢失的操作保留可核查的结果或不确定状态，避免仅因网络断线就盲目重放有副作用的调用。

### 持久化任务、Workspace 与 Agent Memory

- Managed tmux 提供长期任务、持久化输出和 Worker 重启后的任务恢复；长时间调用可通过 durable Wait 继续观察结果。
- Workspace 将 **Goal、Agent Memory、Comment、Approval、Activity 和重新进入（re-entry）** 组织为一致的协作与恢复流程。
- 支持通过 `devshell memory init` / `devshell memory inherit` 管理具名 Agent 工作记忆，保留计划、检查点和协作消息。
- Workspace 由各 Instance 独立启用；普通 ToolCall 的 Inline UI 默认关闭，Fullscreen Workspace 和必要的交互不因此被移除。

### 文件工具、终端和 Artifact

- `bash_run`、`file_read`、`file_grep` 与 `file_edit` 共享受 Context 约束的文件观察和编辑语义；可验证的 Shell 读取结果能够参与文件编辑快照覆盖。
- `file_edit` 支持有序变更集、修改前验证、外部变更冲突检测和部分失败结果保留。
- 终端工具强化 PTY 生命周期、输出背压、任务记录与重连恢复。
- Artifact 支持分享、下载限制、撤销以及跨 Instance 文件传输。

### Extension 与 Agent 系统

- 以能力声明和明确的 Domain API 管理 Extension，支持独立运行时、版本切换、按需激活、热替换和失败清理。
- 提供执行环境与 Sandbox 扩展点；`direnv` 可作为执行环境扩展集成。
- Agent 以平台无关的 `portable-devshell-agent.dsext` 单独发布，支持按需安装并管理 Pi、OpenCode 等 Provider。
- Agent Provider 运行时在客户端独立安装，不随核心 Release 自动安装。

### CLI、TUI、WebUI 与 MCP

- CLI、全屏 TUI、WebUI 和 MCP 统一使用 Control 服务，改进 Instance 状态、Approval、Audit、历史消息和连接变化的呈现。
- MCP 使用现代协议与工具目录，支持显式 Context / OpenAI 会话绑定，以及长时工具调用的 SSE 保活。
- Web 与 MCP 授权提供 OAuth2、PKCE、会话及 Token 生命周期管理。
- 优化 MCP App 的资源加载、Fullscreen Workspace 和交互反馈，减少不必要的 Inline ToolCall 开销。

## 稳定性与恢复能力

本次开发周期重点收口了以下问题：

- **Reverse Worker**：注册与重新配对、离线重连、候选连接切换、Worker 升级及启动就绪状态判定。
- **Instance 生命周期**：删除、重建、并发更新、名称复用及旧代际资源清理，避免过期操作影响新 Instance。
- **Audit 与订阅**：完善分页、持久化写入、事件游标、断线恢复，以及 WebUI/TUI 的状态刷新。
- **Extension**：修复热更新、旧运行代际退休、资源释放与失败恢复的竞争问题。
- **安装与升级**：分阶段准备新版本、保存原有运行状态，在允许回滚的阶段恢复旧版本；强化 Linux、macOS 和 Windows 安装器与跨平台打包行为。

## 安装与升级

**支持平台：** Linux、macOS、Windows，均提供 x64 和 ARM64 的应用包与 Worker。

主程序要求 **Node.js 24.12.0 或更高版本**；使用正式 Release 安装包不需要另行安装 pnpm 或 Rust。

已安装 DevShell 的用户，可在**独立终端或 SSH 会话**中执行：

```bash
devshell update v1.0.0
```

也可从 [GitHub Release 下载页面](https://github.com/Aromatic05/portable-devshell/releases/tag/v1.0.0)获取对应平台的安装包、安装脚本及 SHA-256 校验文件。

### 重要兼容说明

- **1.0.0 不承诺与 0.7.x 的旧 Control、Worker、Frame、MCP 或 Extension 合约兼容。** 应使用相互兼容的组件，并按各自协议版本协商。
- 配置和持久化数据的迁移由实际 Schema 支持范围决定，并非所有历史版本都可直接迁移。升级前请备份配置、数据库和重要的 Instance 数据。
- **不要从待升级 DevShell 自身的 `bash_run` 或 `tmux_run` 执行升级。** 安装器会拒绝这种可能中断自身执行的方式，请使用独立终端或 SSH。
- Agent Extension 需要单独安装；第三方 Provider 运行时不会自动包含在核心应用包中。
- 连接中断后，若无法确定有副作用的 ToolCall 是否完成，应先检查 Audit 与执行状态，而不是直接重试。

完整操作说明见 [安装与升级文档](https://github.com/Aromatic05/portable-devshell/blob/main/docs/getting-started/installation.md)及[兼容性文档](https://github.com/Aromatic05/portable-devshell/blob/main/docs/development/compatibility.md)。
